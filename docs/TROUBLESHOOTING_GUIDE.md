# AP Construction ERP Troubleshooting Guide

Use safe first checks before escalating. Never share passwords, tokens, raw console output, Aadhaar, payroll details, bank details, full backups, or screenshots containing sensitive data.

| Situation | Symptoms | Safe first checks | Do not do | Escalate when |
| --- | --- | --- | --- | --- |
| Invalid username or password | Sign-in fails or credentials are rejected. | Verify the intended email and use the approved Firebase Authentication reset/Console process. | Guess repeatedly, share credentials, or store a password in Firestore. | Multiple legitimate users fail or an account cannot be recovered through the approved process. |
| Forgot password | User cannot sign in. | Use the controlled Firebase Authentication reset/Console procedure. | Ask for the old password or place a temporary password in a spreadsheet/chat/Firestore. | The account identity or Auth configuration is uncertain. |
| Signed in but access denied | User returns to sign-in or sees a permission message. | Verify the matching `users/{uid}` profile exists, is active, and has an approved role. | Share an Admin session or change browser code. | Profile is correct but access still fails. |
| Firestore permission error | A permitted page/action reports permission denied. | Check role, route, site/reference, document status, and the safe visible message. | Weaken rules, use a broad allow rule, or retry an unknown write. | A documented permitted action consistently fails for the correct role. |
| Blank or failed page | Screen remains blank, errors, or never loads. | Refresh once, record the route/time, and have an Admin review System Health. | Create test production records or share raw browser diagnostics. | It reproduces on the current build or affects several users. |
| Build failure | `npm run build` fails. | Read the first real error, confirm dependencies/lockfile, then fix the smallest source issue. | Delete lockfiles, suppress lint/tests, or deploy an unbuilt app. | The error concerns environment/toolchain compatibility or recurs after a focused fix. |
| Deploy timeout or wrong Hosting page | Firebase deploy stalls or an old build appears. | Confirm project, selected target, approved release, build time, and browser/service-worker refresh. | Deploy all Firebase services blindly. | The confirmed Hosting release serves the wrong build or deployment remains incomplete. |
| DPR pending | Field Update says it is saved locally/pending. | Keep the same device and signed-in user, reconnect, review Field Home outbox status, and retry only as directed. | Clear browser data, uninstall the PWA, or submit duplicate DPRs. | A stable connection still produces a non-retryable error. |
| Offline queue not syncing | Pending DPR remains after reconnection. | Confirm online state, active original account, form validity, and attention/retry message. | Transfer another user's queue entry or discard it without approval. | Permission/invalid-data status persists or a stable network cannot synchronize it. |
| Photo upload unavailable | Field Update reports Storage unavailable. | Submit the DPR without photos and preserve evidence through the approved external process if needed. | Delay the DPR, invent photo metadata, or claim Storage is enabled. | Storage has later been formally provisioned and tested but still fails. |
| System Health warning | HEALTHY/DEGRADED/ATTENTION REQUIRED signals need review. | Review sanitized event category, module, code, and time; follow the incident runbook. | Treat it as proof of a Firebase/Google outage or delete events. | P1/P2 criteria, repeated failures, or data-risk signals are present. |
| Missing record | Expected item is not visible. | Check site/date/filter/status, search related module records, and use Audit Log/Data Health where authorized. | Browser bulk restore, unreviewed migration, or deletion of old records. | Evidence suggests loss, corruption, or a confirmed unknown write. |
| Report mismatch suspicion | Totals or progress appear incorrect. | Recheck filters, canonical source documents, site/date/status, and report scope. | Add compensating duplicate income/cost/receipt records. | Correct source records still produce an inconsistency. |
| Git push or OneDrive cleanup prompt | Push fails or Git asks about deleting `.git/objects`. | Answer `n` to the deletion prompt, then verify status, commit, push, and remote history. | Manually delete `.git` object files. | Object errors recur or repository integrity is uncertain. |

For a confirmed incident, follow [Incident Response Runbook](INCIDENT_RESPONSE_RUNBOOK.md). For recovery or a suspected destructive change, stop unsafe writes and use [Backup and Disaster Recovery](DISASTER_RECOVERY.md).
